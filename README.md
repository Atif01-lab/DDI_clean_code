# Drug interactions and bleeding events with direct oral anticoagulants

Analysis code for:

> Ali A, Starkey T, Anand K, Ashraf Kharaz Y, Jorgensen A, Pirmohamed M. *Drug interactions and bleeding events with direct oral anticoagulants: a population-based cohort study.*

A population-based new-user cohort study (CPRD Aurum, 2008-2022, n = 200,140) estimating the risk of serious, minor and all bleeding during exposure to interacting drugs in adults taking DOACs, using time-varying Cox models with multiple imputation of missing eGFR and BMI.

## Data availability

The study used CPRD Aurum data, which are provided under licence and **cannot be shared**. This repository therefore contains **code only**: no patient-level data, no CPRD extracts and no notebook outputs. Researchers with CPRD access can reproduce the analyses by arranging the data as described in [`data/README.md`](data/README.md). The code lists are reported in supplementary tables S1 and S3-S5.

## Methods implemented (summary)

- **Exposure**: prescription end dates from issue date + duration (or quantity / daily dose, otherwise the product median duration). Consecutive prescriptions of the same interacting drug are merged if the gap is < 7 days (antibiotics, antifungals) or < 14 days (all other classes). Exposure is clipped to DOAC follow-up and split into intervals of constant exposure.
- **Outcomes**: serious bleeding (primary-care bleed followed within 7 days by a hospital admission or death), minor bleeding, all bleeding; separate cohorts with outcome-specific follow-up.
- **Models**: lifelines `CoxTimeVaryingFitter`, mutually adjusted for all interacting-drug terms and baseline covariates; NSAID and aspirin (or NSAID class) estimates additionally adjusted for baseline PPI use.
- **Missing data**: eGFR and BMI imputed with `miceforest` (random forests with predictive mean matching, 5 candidate donors, 5 iterations, m = 10), with the event indicator, follow-up time and Nelson-Aalen cumulative hazard in the imputation model; estimates pooled with Rubin's rules. Seeds are fixed in each notebook (`MI_CONFIG["seed"]`).
- **Absolute measures**: rate difference r0 x (HR - 1), with r0 the rate in person-time with no interacting drug active; confidence intervals by the delta method.

## Software requirements

- Python 3.9 (analyses were run with Python 3.9.25) and Jupyter.
- Packages: see [`requirements.txt`](requirements.txt). Key versions used: numpy 1.26.4, pandas 2.3.1, lifelines 0.30.0, miceforest 6.0.4, lightgbm 4.6.0.
- **Linux (or macOS) is required.** The notebooks use `multiprocessing.Pool` with functions defined inside the notebook and rely on the `fork` start method, which is not available on Windows. Use WSL on Windows.
- The analyses are memory- and CPU-intensive (pool sizes of 50-100 worker processes are set in the notebooks; reduce the numbers passed to `Pool(...)` and `MI_CONFIG["n_jobs"]` on smaller machines).

```bash
python3.9 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## How to reproduce

1. Obtain the CPRD Aurum data and code lists and arrange them as in `data/README.md`.
2. Set `DATA_DIR` and `OUTPUT_DIR` in `analysis/paths.py`, or export `DDI_DATA_DIR` and `DDI_OUTPUT_DIR`.
3. Start Jupyter **from the `analysis/` folder** (so that `paths.py` and `lag_sensitivity.py` can be imported) and run the notebooks top to bottom in numerical order:
   - 01 -> 02 -> 03 (cohort, covariates, Table 1)
   - 04 -> 05 -> 06 -> 07 (main hazard-ratio analyses; 07 must precede 08)
   - 08, 09, 10 (supplementary characteristics and analyses)
   - 11, 12 (absolute measures, figures and tables; require 04-07)
   - 13-23 (sensitivity analyses; 21 requires 04-07 and 17-20)

   For example, non-interactively:
   ```bash
   cd analysis
   jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 01_cohort_creation.ipynb
   ```
4. Aggregate results are written to `outputs/results`, `outputs/supplementary`, `outputs/sensitivity` and figures to `outputs/figures`. Patient-level intermediate files are written to `outputs/derived` and must remain within the secure environment.

Before sharing any output, apply CPRD's rules on small cell counts.
